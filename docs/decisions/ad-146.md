# AD-146 — Antigravity CLI is a provider, built only from what agy 1.2.16 was observed to do

- **status**: active

## Decision

1. **`src/providers/antigravity/` is a third adapter**, registered last in `provider.registry.ts`. It is
   detected by `conversationId` (string) + `workspacePaths` (array) **and the absence of `hook_event_name`** —
   the field every Claude and Cursor payload carries — so the three detections are disjoint by construction.
   A test resolves every captured fixture of all three hosts and asserts each matches only its own adapter.
2. **The event name travels in the hook's environment.** The wiring writes each command as
   `TLC_AGY_EVENT=<Event> node <launcher> <handler>`, and `antigravityToEvent` reads
   `process.env.TLC_AGY_EVENT`. When the variable is absent, a payload with `toolCall` is `PreToolUse` (or
   `PostToolUse` when it also carries `error`), and one with `terminationReason` is `Stop`. An invocation payload
   with no variable is unrecognized, never guessed.
3. **Mapping.** `PreInvocation` with `invocationNum === 0` → `prompt.submit` (handler `prompt-submit`); any other
   `PreInvocation`, including one without a numeric `invocationNum`, is unrecognized; `PreToolUse` → `tool.before`, fanned
   out by `toolCall.name` (`run_command` → `shell.before`, `call_mcp_tool` → `mcp.before`, `view_file` →
   `read.before`); `PostToolUse` → `tool.after`, or `tool.failure` when `error` is non-empty, fanned out the same
   way (`write_to_file`/`replace_file_content` → `edit.after`); `Stop` → `stop`, with `status: "error"` when its
   `error` is non-empty. `PostInvocation` is not mapped and not wired.
4. **Tool names are translated where the rails need them**: `write_to_file` → `Write` (with `TargetFile` as
   `filePath` and `CodeContent` as `proposedContent`), `replace_file_content` → `Edit`, and an MCP call →
   `mcp__<ServerName>__<ToolName>` with `Arguments` as `toolInput`. Any other tool carrying a string `TargetFile`
   → `Edit`; every other tool keeps the host's name.
5. **Capabilities**: `enforcesHooks` true; everything else false or empty — no `ask`, no context on any event,
   no input or output rewrite, no tool output at after. `render` answers `{"decision":"allow"}`,
   `{"decision":"deny","reason":…}`, `{"decision":"continue","reason":…}`, and `{}` for abstain; an `ask` or a
   `rewriteInput` that reaches render is rendered as a deny carrying its reason.
6. **`ProviderWiring.strategy` gains `named-merge`.** agy's hooks file (`~/.gemini/config/hooks.json`) is an
   object of named hook sets; ours is `tlc-harness`, replaced whole on every write, and every other set keeps its
   value and position. `bin/write-user-hooks.mjs`, `tools/doctor.ts` and `tools/uninstall-runtime.ts` dispatch
   on it explicitly.
7. **`ProviderPort.wiringTargets(projectDir?)`.** `run.ts` passes the event's project, and the agy adapter adds
   `<project>/.agents/hooks.json` to the floor's protected paths.
8. **`transcriptPath` is not surfaced** for agy events, and the lessons view is `null`.
9. **`TLC_AGY_EVENT` is scrubbed from the test environment** in a list of its own, `HOOK_SCOPED_ENV`.
10. **The session's claims are released at a Stop that lets the agent stop.** `HarnessEvent` gains
    `sessionEndUnreported?: boolean`, set by the agy adapter on every `stop`. The `stop` entrypoint calls
    `presence.release` after deciding, when the flag is set and the decision is not `continue`. No other part of
    `session-end` runs, and no hook is added to the wiring.
11. **A command's relative paths resolve in the directory the call names.** `HarnessEvent` gains
    `commandCwd?: string`, set by the agy adapter from `run_command`'s `Cwd`; `tool-before` passes it to the floor
    as `FloorInput.commandCwd`, which resolves the shell words (destruction targets, the policy surface, wiring
    targets, secret reads) against it. The project boundary stays `projectDir`.
12. **A `run_command` with an empty `error` is a success, because nothing better is observable.** It maps to
    `shell.after` with its command, so it records a proof. No transcript is read.

## Why

**Observed, not read.** agy 1.2.16 was driven with `agy -p` against a workspace hook that wrote each stdin to
a file and answered with each candidate response. A PreToolUse deny stopped the tool and the model received
`tool call denied by pre-tool hook: <reason>`; a Stop `continue` made the agent run the command named in its
`reason`; `{}` at Stop let it end. Nothing else was verified, so nothing else is declared — the same rule
[/decisions/ad-050.md](/decisions/ad-050.md) applies to a field that exists and is dropped.

**Why the environment, and not the port.** The port hands `toEvent` the payload only, and that is what keeps
`run.ts` and core ignorant of which host is speaking ([/decisions/ad-004.md](/decisions/ad-004.md)). The handler
name does not decide it either: PreInvocation and PostInvocation payloads are byte-identical, and the handler is
not passed to the adapter. A leading assignment in the command reaches the launcher, which hands its whole
environment to the entrypoint — and it is the channel the Orca hook on the same machine already uses
(`ORCA_ANTIGRAVITY_EVENT='Stop' /bin/sh …`), so it is known to work in agy's hook runner. The shape fallback
exists because that assignment depends on a POSIX shell, and the deny path is the one that must not depend on
it.

**Why translate the write tools.** The floor's wiring-tamper rule, the edit-collision check, the comment gate
and the presence claim (`isWriteTool`) all key on `Write`/`Edit` ([/decisions/ad-010.md](/decisions/ad-010.md)).
Untranslated, `write_to_file` onto `~/.gemini/config/hooks.json` reads as an unknown tool and passes every one
of them. The MCP name takes the shape the rule grammar already normalises ([/decisions/ad-135.md](/decisions/ad-135.md)).

**Why a new strategy.** The installer dispatched two ways — `replace` to the Cursor writer, everything else to
the Claude merge. Registering agy with `merge` would have rewritten its file into Claude's schema on the next
`tlc harness update`, deleting nothing but making the harness's entries unreadable to agy and the file a mix of
two schemas; and that file already holds the Orca hook. Owning one named set is also what makes idempotence
and removal exact: the comparison is one deep-equal on one key.

**Why the workspace file is protected.** agy loads `<workspace>/.agents/hooks.json` without asking, even in an
untrusted directory under `-p`. An agent that can write it can unregister the harness for its next session — the
same tampering the global file is protected against. It is protected whichever host's agent writes it.

**Why no transcript.** `tool-after.ts` reads `event.transcriptPath` with the only transcript reader there is,
built for another host's format, whenever `usageInPayload` is false. agy's transcript is its own JSONL.

**Why only the first invocation is a turn.** Measured against the real binary: one short task produced 56
`PreInvocation` events, one per model call, `invocationNum` counting from 0. Each became a `prompt.submit`, so
the once-per-turn markers were cleared mid-turn and the turn base was re-captured after the turn's own edits.
A payload without the counter is ignored, not taken as `0`: a missed boundary falls back to `HEAD`, the default
[/decisions/ad-144.md](/decisions/ad-144.md) already treats as safe, while a false one corrupts the turn.

**Why the claims are released at Stop, and only there.** Also measured: an `agy -p` run's file claim outlived
it by the ten-minute stale window, and the next run's `Write` to the same file was refused as `edit-collision`
three times. On other hosts `session-end` releases it, and agy has no such event. A second Stop hook running
`session-end` was rejected: that handler also resets the stop-loop counter, and on a host where every turn ends
in a Stop the reset would run on each one and the grind cap would never be reached. The flag lives on the event,
not in a capability, because it is one fact about one event kind and the core reads it in one place. Releasing on
`continue` is not harmless: the agent keeps working, its claims cover every file it wrote that turn, and only the
next file it writes is reclaimed (the heartbeat in `run.ts` claims on each write).

**Why `commandCwd` is its own field.** Found by review: `Cwd` is chosen per call, and resolving relative words
against the project let `echo '{}' > hooks.json` from the global hooks directory, and a `../` climb from a
subdirectory into the project's policy file, both pass. `cwd` already exists, but Claude sets it on every event
and Cursor on every shell, from session state — a worktree outside the project is an ordinary value there, and
resolving against it would turn their relative `rm` into an outside-project destruction. A field only a host whose
call carries the directory sets keeps their behaviour exactly as it was.

**Why an unknown tool with `TargetFile` is an `Edit`.** Also found by review: `multi_replace_file_content` on the
global hooks file passed the floor and operator `tool(Edit)` rules as an unknown tool. The edit tools were never
all observed, so naming a target file is taken as writing it. Failing closed costs a tool that only reads by
`TargetFile` an edit-collision ask at worst; failing open let a write through.

**Why an empty `error` counts as a pass.** Both facts verified against the real binary: a `run_command` that
exits 2 arrives at PostToolUse with `error: ""`, exactly like a success; and the transcript does not contain the
step's result when PostToolUse fires — only earlier steps are there, and waiting 3 s inside the hook does not change
it, because agy writes the step after the hooks return. Reading the exit code from the transcript, with an
unreadable outcome proving nothing, was implemented and reverted: the step is never readable, so no command ever
counted — measured, a passing `ruff format --check` was then reported missing at push, and a rule proven by a
command (a context rule gating every write) could never be satisfied, which locks the agent out for good. Between a
proof that a red command can satisfy and a proof nothing can satisfy, the first keeps the harness usable and the
grind still checks the real result at Stop.

## Trade-offs

**On agy, a `command(…)` proof can be satisfied by a command that failed.** A rule such as verify-before-push
is weaker there than on Claude, where the failure is a PostToolUseFailure. The stop-time grind, which runs the
gates itself, is what catches a red result.

**Every model call after the first leaves an `adapter.unrecognized` record.** `run.ts` records any payload the
adapter declines, in the workspace's `obs.jsonl` at signal level — one per ignored `PreInvocation`. The readers
that tail that plane filter by kind, so nothing they count is pushed out, but the plane is noisier. A port-level
"ignored on purpose" outcome would remove it; it is not decided here.

**In an interactive agy conversation, claims are released at the end of every turn.** Between turns another
session's write to the same file is no longer asked about — weaker than Claude, which keeps its claims until
`SessionEnd`. A run killed before its Stop keeps its claims for the stale window, as before.

**A `tool.failure` is handled by the `tool-after` entrypoint.** agy has one PostToolUse registration, so a
failed tool arrives at `tool-after` with `event: "tool.failure"`. Rule observation ignores it (it records only
`tool.after`/`shell.after`/`edit.after`), so a failure never counts as proof; the cost is that it is audited
under `tool-after` and does not emit the `tool.fail` observation `tool-failure.ts` would.

**The event variable needs a POSIX shell.** On a host that runs the command without one, invocation events go
unrecognized (no turn boundary, so stop-time gates diff against `HEAD`) while tool events and Stop still work by
shape. Windows was not tried.

**Edit tools are recognised by `TargetFile`, not by name.** `replace_file_content` and
`multi_replace_file_content` were never captured. An edit tool that names its file in some other field still
reaches only the generic `tool.before` path, where the floor's file checks do not see a write.

**Claude and Cursor keep resolving relative shell words against the project.** A Claude session that `cd`s
elsewhere in one command and writes a relative path in the next is resolved at the project root, as before —
the same class of gap `commandCwd` closes for agy, left open there because their `cwd` is session state.

**The workspace hooks file is protected for every host's agent.** A Claude session in a repository that keeps
`.agents/hooks.json` can no longer edit it with a tool; the operator edits it from their own terminal. The
project-level `.claude/settings.json` and `.cursor/hooks.json` are not protected the same way, which is an
asymmetry this record does not resolve.

**No launcher canonicalisation in the health check.** Claude's comparison resolves the launcher through
symlinks because it is a standalone argument; here it is inside a command string. A runtime home reached
through two different paths reads as `detected-but-unwired` until the next update rewrites the set.

## Not decided here

- **The real names of agy's edit tools.**
- **Reconciling a command's outcome on the next event.** When the next `PreInvocation` (`invocationNum > 0`),
  `PreToolUse` or `Stop` arrives, the previous step is in the transcript; its exit code could revoke a proof the
  command should not have earned. That needs proof revocation in the core, which does not exist.
- **Resolving Claude's and Cursor's relative shell words against their reported `cwd`.**

- **`invocationNum` in an interactive conversation.** Only `agy -p` was observed. If the counter does not restart
  at each prompt, later prompts get no turn boundary.

- **Context injection on agy.** The response field for PreInvocation context was not found; the capabilities
  stay false until a payload proves one.
- **`ask` on agy.** Never observed. Until it is, every escalation is a deny that says why.
- **Project-level agy wiring from `tlc harness init`.** `mergeAntigravityHooks` writes any target, but the init
  wizard still writes shims only for Cursor and Claude.
- **A lessons view for agy.** Which file agy reads as standing instructions was not established.
- **Protecting the project-level Claude and Cursor hook files** the way the agy workspace file now is.
